# Agent PAT-to-JWT Authentication (supersedes Identity Service login)

Accounts, login, registration and refresh tokens are removed. Authentication follows `docs/agent-jwt-contract.md`: the long-lived `sagein_pat_...` written by `sagein-community` (scope `skill_jwt`) is exchanged at `POST <origin>/api/agent/jwt` for a short-lived JWT (default 24h), and gateway parameters (`baseUrl`, `tokenHeader`, `issuer`, `audience`, `kid`, `tokenExpiresIn`) come from the public `GET <origin>/api/agent/asynx-config`. Requests to the Asset Gateway authenticate only via the `X-Asynx-Partner-Token` header (never `Authorization`), proactively refreshing within 60 seconds of expiry or on `kid`/`iss`/`aud` mismatch, and retrying once on HTTP `401 invalid_partner_token`. The PAT never leaves the local machine except to SageIn; a missing PAT yields `need_login`, a missing scope yields `scope_missing`.

**Amended 2026-11-19 (credential lookup):** the Skills no longer read the PAT, call `POST /api/agent/jwt`, or cache the JWT in `~/.config/asynx/config.json`. Every JWT comes from running the exact `get-skill-jwt.mjs` argv that the Plaiers installer records in `.plaiers-context.json` next to the installed package. That bridge keys its cache by site + Agent + account + PAT and checks `sub`. Binding scans, the legacy `credentials/<sha256(origin)[:16]>.json` fallback, `SAGEIN_COMMUNITY_*` lookups and the `https://plaiers.ai` default origin are removed. A missing or invalid context yields `need_login`. On gateway 401 the bridge is re-run once, and an unchanged JWT is not retried. JWT validation (`kid`/`iss`/`aud`/`exp` against `asynx-config`) and the `X-Asynx-Partner-Token` header are unchanged. Reason: the unkeyed cache and binding discovery reproduced PR tanqunzhao/Plaiers#10 finding P1, where switching account, Agent or PAT could reuse another identity's token. ADR-0007 will consolidate this with registry distribution.
